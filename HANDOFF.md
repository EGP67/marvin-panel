# HEART OF GOLD — Marvin telemetry panel (hog.local)

## What it is
Permanent portrait 1080x1920 telemetry panel behind the glass side panel of an Ubuntu
homelab server (hog.local). Rendered as MARVIN: bleak, sardonic, self-pitying,
occasionally useful. Title is "HEART OF GOLD" (the ship); every spoken line is Marvin's
and stays attributed to him.

## Status of the physical build
THE PANEL IS NOT YET PURCHASED OR INSTALLED. Until it exists there is nothing to look at:
development proceeds against fixture data and browser screenshots only.
It will connect to the MOTHERBOARD HDMI port, which on this CPU is the integrated
graphics (amdgpu), NOT either Nvidia card. The panel must therefore never require or
allocate Nvidia GPU work. Read docs/DISCOVERY.md and docs/PANEL_BUYING.md first.

## Hard constraints
- Portrait 1080x1920. No keyboard, no mouse, no interaction of any kind, ever. Always on.
- Must never endanger the host it monitors: non-root user, CPU/RAM capped, restart always.
- Any unavailable metric renders as visible text saying so. Never a silent zero.
- Renderer must be software-rasterised. The iGPU only scans out the framebuffer; the two
  Nvidia GPUs are reserved for inference and must stay at 0% because of this app.
- Marvin runs on the box he reports. His own process appears in his own process list.

## Architecture (DECIDED — do not re-litigate)
1. marvind    single Go binary. Collects, computes, owns state + mood + phrase choice.
              Serves JSON on 127.0.0.1 only. No external network, no auth (loopback).
2. front end  one static HTML page embedding the SVG from mockup.svg. Polls
              /snapshot.json at 1Hz and mutates SVG attributes/text in place.
              No framework, no bundler, no build step for web/.
3. display    chromium --app --kiosk --disable-gpu, or Linux console fallback.
4. rationale  mutating attributes on an existing SVG is ~free; regenerating whole frames
              is not. Collection and presentation stay independently testable, which is
              what makes fixture-driven development and CI checks possible.

## Quality gate — MANDATORY on every build, no exceptions
make verify   runs: golangci-lint run ./...
                       go test -race ./...
                       govulncheck ./...
                       gitleaks detect --source . --redact
A task is not complete until make verify exits 0. govulncheck needs network; if the host
is offline, say so in your report rather than skipping it silently.

## Definition of done
Panel shows: title | phrase box | PROCESSOR (model string, total util % coloured by CPU
temp band, "GHz | TEMP n°F / m°C", 120s utilisation graph, per-thread dot matrices) |
GRAPHICS (total + GPU0/GPU1 model + vRAM + F/C + sparkline) | MEMORY | NETWORK split row
| STORAGE I/O | SPACE split row | THERMALS (CPU/GPU0/GPU1/NVME in F and C, FAN BANK 1/2
RPM if they exist) | footer (load, uptime, DON'T PANIC).
Runs at boot. Survives 24h with flat RSS. Under 2% of one core idle. make verify clean.

## Escalation triggers — stop and ask rather than attempt a 4th time
1. Same task fails 3 times. 2. Multi-file data-model refactor.
3. Display/kiosk/rotation/EDID plumbing. 4. Code that works but is not understood.
